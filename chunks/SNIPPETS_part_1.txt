# Task: Procedural Planet-Unique Block Textures (Pixel-Art Atlas)

You are editing a Minecraft-style voxel game (manscraft / VoxelCraft). Planets are already fully procedural (space scene, surface terrain, theme/flora). **Block textures are still generic** — one shared atlas is painted once with fixed base colors, then **only multiplied by per-planet RGB tints**. That makes every planet look like the same grass/dirt/stone with a hue shift.

## Goal

1. **Each planet’s unique blocks get their own distinct procedural textures in the atlas** — real pattern/structure differences (blade streaks, clump noise, dirt flecks, stone cracks, leaf silhouettes, bark rings, flower petals), **not just tinting**.
2. Procedural textures must look like **hand-drawn 16×16 Minecraft pixel art** (nearest-neighbor, limited palette, intentional dither/speckle, crisp edges, no blurry noise soup).
3. **Fix blank / invisible / washed-out grass** (grass block tops and tall-grass cutouts).


### Reference look (target aesthetic), **IMPORTANT** each must have their own color palette

- Lush plains/forest floor: **grass tops with visible pixel variation**, not flat tint slabs.
- Heavy **flower field** (many cross/billboard flowers),.
- Tall **conifer/broadleaf voxel trees**: trunks, multi canopy blocks with holes (cutout leaves).
- Dirt/side of grass blocks visible on slopes with a **jagged grass overhang** on the side tile.
- No blank/pink-missing/alpha-punched grass tops; tall grass blades must sample a real tallgrass not empty atlas cells.

---

## Hard constraints

- Keep atlas model: **16×16 tiles**, packed grid, `NearestFilter`, no mipmaps, `SRGBColorSpace`.
- `createTextures(theme)` is called once per planet landing in `engine.init` — **seed painters from `theme.seed` / `theme.originTag` / `theme.type`** so the same planet is stable across sessions.
- Do **not** rely only on `tintTile` / `tintsFromTheme` / `originTints` for identity. Tint may remain as a *secondary* grade; **primary identity must come from painter logic + per-planet palette stops**.
- Preserve tile indices (`TILES.*`) and `tileUV` layout unless you deliberately expand the atlas (if you add tiles, update `TILE_NAMES`, block defs, mesher).
- Cutout tiles (`tallgrass`, `leaves`, flowers, torch, glass, stick, coal item) **must write real alpha** (`put(..., a)`); transparent pixels stay `a=0`. Blank grass is often caused by all-null painters, wrong UV, or alphaTest eating near-empty tiles.
- `emitTallGrass` / cutout materials use `alphaTest: 0.4` — blades need **opaque green pixels** covering enough of the quad UVs.
- Prefer extending `src/game/core/textures.ts` (+ small hooks in theme/origin if needed). Avoid breaking conveyor animation (`animateConveyorTiles`) and ore/machine tiles unless theming them similarly.

## Architecture (current → desired)

### Current (problem)

```
createTextures(theme)
  → paint every tile with FIXED base RGB painters (same for all planets)
  → optionally multiply pixels by tintsFromTheme(theme)  // generic look
```

### Desired

```
createTextures(theme)
  → derive PlanetPaintContext from theme (type, seed, originTag, palette stops, flora hints)
  → for each organic/surface tile, run a PLANET-AWARE painter that:
        picks a small hand-authored-style palette (4–6 colors) from planet ramps
        draws Minecraft-like motifs with seeded RNG (hash per pixel / feature)
        varies motif by planet type (terran grass ≠ crimson grass ≠ neon grass ≠ ice grass)
  → machines/ores may stay mostly universal
  → optional light grade/tint only after paint, not instead of paint
```

Planet types that must feel obviously different on **grass_top / grass_side / dirt / leaves / log / tallgrass / flowers** at minimum:

`terran | ocean | desert | ice | oceanic_ice | volcanic | lava | barren | alien | jungle | savanna | tundra | crimson | neon`

## Pixel-art painter guidelines (implement these techniques)

Work in **integer pixel space** 0..15. Use a seeded `mulberry32` / `pixelHash`.

1. **Palette first**: 1 shadow, 2 mid, 1 highlight, optional accent (flowers, biolum, frost). Sample from `PLANET_PALETTES[type].stops` via existing `rampAt` / `groupTargetRgb` / `originGroupHex`, then **quantize** slightly so it feels painted.
2. **Base fill** with low-amplitude value noise (not HSV noise soup).
3. **Motifs**:
   - `grass_top`: diagonal blade clusters, tiny dirt holes, occasional flower speck; Minecraft-like patchy tufts.
   - `grass_side`: dirt body + top 2–5 px grass lip with irregular edge array (already started).
   - `dirt`: pebbles + dark pits.
   - `stone` / `cobble`: cracks, blobs, mortar lines.
   - `leaves`: ~10–20% holes (`null` alpha), clustered leaf pixels, vein darker dots.
   - `log_side`: vertical bark striations; `log_top`: concentric rings.
   - `tallgrass`: 5–9 single-pixel blades with lean; **never return an empty tile**.
   - flowers: stem + petal disc matching planet accents (lavender for lush terran meadow look).
4. **Outline / contact shadow**: darken bottom row or one side lightly for “hand-drawn” weight.
5. **Determinism**: `mulberry32(planetSeedSalt ^ tileIndex * 7919)` plus `pixelHash(x,y,salt)`.

### Blank grass — known failure modes to fix

1. `tallgrass` painter returns `null` for every pixel → alphaTest discards whole quad.
2. Grass top painted too dark then over-tinted toward black/zero.
3. `grassShape.present === false` skips mesh emission for some planet types (volcanic/lava/barren/desert ice) — OK for those; **terran/jungle/savanna/alien/neon must present**.
4. Side/top tile index mismatch in `DEFS[B.GRASS]` / `DEFS[B.TALLGRASS]`.
5. After procedural regen, atlas `needsUpdate` / materials still pointing at old texture (recreate path in `engine.init` is fine if textures rebuilt there).

**Fix requirements:**

- Guarantee `grass_top`, `grass_side`, and `tallgrass` always have visible opaque pixels for planets where grass exists.
- For flower-heavy meadow planets, bias flower petal colors toward **lavender** (reference)
- Ensure cutout UVs still map to the painted tallgrass/flower tiles.
