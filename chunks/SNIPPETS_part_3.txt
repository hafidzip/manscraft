 * Derived from the OLD `sunDir()` evaluated at `time = 0.16` (mid-morning), the
 * frame the golden-hour palette was tuned against:
 *   a      = 0.16 * 2PI              = 1.00531
 *   elev   = goldenElevation(sin a)  = GOLDEN_ELEV = 0.22   (plateau)
 *   horiz  = sqrt(1 - 0.22^2)        = 0.97550
 *   hx     = cos a = 0.53583, hz = 0.35 -> normalised (0.83683, 0.54756)
 *   dir    = (0.81632, 0.22, 0.53415)                      (already unit length)
 *
 * These are `const` for the whole session: the shadow direction can never change,
 * which is the precondition for texel snapping (Task 4) and for the frozen,
 * view-independent grass pose (Task 3).
 */
export const SUN_DIR  = new THREE.Vector3( 0.81632, 0.22, 0.53415).normalize();
/** Moon: mirrored azimuth, lifted to 0.34 so night shadows have usable length. */
export const MOON_DIR = new THREE.Vector3(-0.81632, 0.34, -0.53415).normalize();
/** Distance the light rigs are pushed back along their direction. */
export const CELESTIAL_DISTANCE = 140;
```

# TASK 4 — Shadow LOD (done before Task 3, because Task 3 depends on its constants)

## 4.0 Design

Two cascades, **not** two lights:

| | Near cascade | Far cascade |
|---|---|---|
| Owner | existing `sun`/`moon` `DirectionalLight` (three renders it) | new manual RT pass (`ShadowLod`) |
| Size | 2048² | 1024² |
| Half-extent | **32 m** (was 44) | **96 m** |
| Texel | **3.125 cm** (was 4.30 cm → **1.4× sharper**) ✅ crit. 2 | 18.75 cm |
| Casters | terrain + leaves + **grass** | terrain + leaves only (layer-filtered) |
| Refresh | existing throttle + geometry-dirty | only when the player leaves an 8 m cell, or geometry changes |
| Applied | three's own `getShadow` | custom 4-tap PCF, weighted by view depth |

Why a **manual** far pass rather than a second `DirectionalLight`:
`WebGLShadowMap.renderObject` tests `object.layers` against the **view camera**, not the
shadow camera — so a second light *cannot* be made to skip grass. A manual pass uses its
own camera, so `farCam.layers.set(LAYER_FAR_CASTER)` gives exact caster control, avoids a
wasted per-fragment PCF for a zero-intensity light, avoids depending on directional-light
array ordering, and lets the far map be **cached for tens of seconds** (the payoff of the
static sun).

**Range reality check.** `uFarFogEnd = (VIEW_DISTANCE+0.75)·16·0.92 = 84.6 m`, and only
`VIEW_DISTANCE = 5` (80 m) of chunks are meshed. Shadows past ~85 m are behind opaque fog
and have no casters. So the far cascade is sized 96 m and faded out **72 → 88 m**: that is
**2.7× today's 32 m effective near range** and 100 % of what is physically visible. Raising
it further is a one-line change to `SHADOW_FAR_HALF_EXTENT` *if* `VIEW_DISTANCE` is raised.
