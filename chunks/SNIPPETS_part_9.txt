## 5.0 The bug in one line

`harvestOutcome` returns `null` for anything missing from `TO_FPS`, and `updateMining`

## 5.3 Drop decision — **Option A: plants drop nothing** (criterion 3)

Chosen deliberately. Option B (real plant items) requires four coordinated edits in two
different id spaces (`TO_FPS`/`FROM_FPS` world→fps, plus `BLOCK_NAMES` and
`BLOCK_SELL_PRICES` keyed by *fps* ids) **and** a drawable icon for every new fps id,
because `itemDrops.prewarm(new Set(Object.values(TO_FPS)))` runs at load and an unknown id
renders garbage. That is a content task, not a bug fix, and it is the documented risk in
the brief. If you do want it later, the minimal set is:

```ts
TO_FPS[B.TALLGRASS] = 66;  TO_FPS[B.FLOWER_RED] = 67;  TO_FPS[B.FLOWER_YELLOW] = 68;
// FROM_FPS is derived automatically; then BLOCK_NAMES[66..68], BLOCK_SELL_PRICES[66..68] = 0,
// and an icon for 66/67/68 in the item-drop instancer.
```

Adding those three entries makes `harvestOutcome`'s first branch win, and 5.1's plant
branch becomes dead code that harms nothing — the fix is forward-compatible.
